# 新增空白任務先開啟原表單

第二輪正式測量中，第一次新增任務仍須等同仁名單完成，才出現可輸入的原表單。三個獨立內建瀏覽器新分頁、同一既有登入，實際按新增至原生表單及名稱欄可輸入為 3,120／5,644／5,843 ms。這些是文件載入完成後的首次開啟，不含完整開站或 Android LINE 導頁；網路與背景工作仍有波動。同頁重開使用原人員快取，不與這組混算。

本包僅處理沒有既存草稿的一般空白新增，先顯示原單一表單供輸入名稱與說明。人員未確認前，保留原 `readReady` 送出檢查並停用其他寫入入口；名單成功後在原表單補齊選項、本人預設與原操作。名單失敗可重試且保留輸入；取消、換表單或換身分後的結果不可沿用。

原草稿、建立待重試、待辦指派及特殊 HR／日常入口繼續使用原初始化。原草稿存回、關閉確認、附件控制器、工作 ID 與操作 ID 都保持。固定程式檔轉換仍在最外層版本快取之前，登入與業務資料不快取。

新增的非同步路徑持續核對原帳號、工作 ID 與同一張表單；AI 名稱、重複專案查詢、裝置待送保存、附件處理及恢復未完成內容，等待後都不能改存到另一帳號。明確送出且已留存的命令仍可在同帳號背景完成，但不會清除或關閉後來開啟的卡片。換帳號後保留原帳號的待送內容，原帳號可再重試。

可輸入與人員確認完成是兩個終點，必須各自量測。這個介面改善不代表人員查詢、完整工作清單或正式儲存已變成零等待。後續完整測試、正式版本及實測結果依完成證據補登。
