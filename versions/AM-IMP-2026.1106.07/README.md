# 會議清單讀取與來源核對改善

狀態：Ready。延續 AM-IMP-2026.1106.06 的正式分段量測，處理工作日誌會議分頁中約 2.8–4.1 秒的清單階段。

前輪已發布，但同條件三次可見時間中位數為 8,861→8,610 ms，範圍重疊，沒有認定穩定加速。這輪不重發 DailyLog 或 UOF，只調整 AM 的會議清單讀取。

- 前 40 筆清單原本取出完整會議欄位，包含清單沒有使用的長內容。改為只取卡片、待辦數、本人 Calendar、來源與發布核對實際使用的欄位；原資料、篩選、排序、40 筆分頁與回覆內容保持。
- 先將需要核對的來源分組，每次最多同時讀 5 個不同來源，避免相同來源重複佔住處理位置。每場會議的替代權限與最後的來源重新核對保持。

同一正式資料的唯讀交易比對，前 40 筆取回資料由 4,147,195 降為 89,384 bytes，所有卡片所需內容保持。外部 PostgreSQL 連線的三次交錯測試原為 3,683／3,200／3,148 ms，新為 189／185／196 ms；這是外部連線證據，不是 Render 正式頁面速度。發布後必須以原登入、同樣分頁操作再次量測。

沒有新增跨請求權限快取，既有登入核對時點及人員同步記憶保持。原始資料、設定及來源比對只留私人目錄。
