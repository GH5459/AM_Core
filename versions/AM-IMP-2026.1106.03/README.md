第二輪同帳號正式讀取各三次，中位數：任務清單 7,478→7,756 ms、詳情 4,362→4,408 ms、會議清單 6,152→8,289 ms、會議內容 5,297→5,301 ms。UOF 重新登入後同帳號空清單為 3,002→2,825 ms，不能代表多案件。首次新增表單僅各一次 3,483→3,120 ms；同頁再次開啟 71／70→72／140 ms 另列，不能混稱首次加速。第一輪 UOF 較慢與會議內容沒有明顯改善的紀錄保持。

第二輪選定快照的 774 件任務、44 筆身分設定、110 個附件紀錄、191 筆分塊資訊、58 筆會議及 42 筆 UOF 工作保持。初始 769 件任務全部保留，期間 6 件版本追加及 5 件新增的歷史保留，原 56 筆會議另有 2 筆新增。附件沒有另下載原始分塊 bytes；會議快照不涵蓋獨立編修歷史、派發或翻譯資料表。沒有真人業務測寫、資料回灌或實體 Android LINE 驗收。

DailyLog 的 GET 任務、詳情及人員查詢使用僅限同一次內部 Request 的身分回覆，省去沒有使用到的主管範圍計算及完整登入回覆組裝。公開登入 API 仍回覆完整內容，首次帳號登記、名單同步、過期／停權／復職及回傳前的最新權限檢查保持。沒有新增跨請求權限快取，也沒有預先下載人員資料。

UOF 將互相獨立的分類補讀同時進行，保留每批上限、同帳戶與同站點核對、原失敗回覆。兩層之間有綁定檢查的登入核對仍各自讀取最新結果；原簽核提交不變。新增只含固定區段名稱的耗時計量，方便區分登入、資料查詢及呈現的等待。

會議只讀路徑將同階段獨立資格、語系及進度查詢同時進行，減少同次重複身分讀取；各次請求仍重新核對，進度只有在主持人與檢視者核對全部完成後才讀取。原寫入、發布及派發流程保持。

本包只含通用程式與合成測試。完整現場模組、真人資料快照、秘密及原始量測只留在私人發布目錄。隔離延遲比較與正式瀏覽器速度分開報告，不用減少傳輸量代替等待時間驗收。
