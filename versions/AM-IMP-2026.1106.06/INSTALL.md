# 安裝

1. 擷取當下 DailyLog 的 active、latest、完整模組、設定、秘密參照、資源綁定與兩個排程。只在 active 與 latest 都是同一個 100% 正式版時準備候選；若有並行新版，先以新版本重新建立及驗證。
2. 在私人目錄複製完整模組，套用本包兩項精確修補。保留其他模組原始 bytes，不在 dirty 專案根重建整包；沒有修改資料表或真人資料。
3. 執行本包測試、完整 Worker 隔離測試、原功能測試與六寬檢查。來源審查完成、完整 CI 通過、合併後程式樹一致，才可發布。
4. **先發布 DailyLog 新增的合併查詢入口與窄身分支援，再部署 AM 的清單使用端。** 新入口沿原服務驗證；未驗證服務仍拒絕。
5. AM 必須從已合併並推送 GitHub main 的精確 commit 部署至原服務。不得從本機分支、dirty 工作目錄或舊 main 發布。
6. 回讀 DailyLog 全部模組、設定與排程，確認 AM 兩個正式來源及 Render Live；比較選定資料快照，保留自然並行變更，不回灌舊資料。
7. 以同帳號、獨立分頁、實際按會議分頁再測三次。分開報告點擊至清單可見及後端耗時，包含沒有改善或變慢的樣本。

HOZO_AM、SevenAM 舊獨立服務沒有使用此工作日誌內嵌路徑，不複製其他專案資料或部署設定。共享與專案紀錄只記本次真正驗證的目標。
