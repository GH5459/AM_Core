# 工作日誌與 UOF 入口加速

工作日誌指令沿目前 LINE 選單的精確設定，先開原日誌網站，以原完整登入及權限程式渲染。跨站第一次沒有 Strict Cookie 時先在同來源重進一次；確實未登入才回到原 LINE 身分確認網址。現有登入不必每次先等待 LIFF。首次連結、公司驗證及原會議入口保持。

工作清單將舊日誌匯入查找、分享上下文與同步狀態改成批次讀取，保留原任務、Notion 同步、分享、最後權限及版本重核。沒有跨請求的私人資料或權限快取。日誌保存、手機待送內容、私密 iframe 與自動整理維持原程式。

正式重測後再補強：把任務清單重複查找的專案關係一次讀取，維持原可見性判斷並增加回傳前關聯版本核對。LINE 快速入口直接使用原完整頁面處理器已驗證的本人資料與原 bootstrap 產生式，連同原語言設定放在同一份 private/no-store HTML；原其他網址的 bootstrap 接口保持。原表單與私密 iframe 不重建，不移除裝置資料。followup-worker.cjs 僅可精準延伸已部署第一階段的完整 83 模組包，不能從舊 82 模組整包覆蓋。

UOF 新進入接口在外層 Worker 並行呼叫原 session 與 web-pending，瀏覽器一次取得原身分及本人最新清單。兩個原接口各自保持驗證；錯帳號、讀取失敗與無資格不能變成成功空清單。原 DO 類別與簽核處理程式 bytes 不改，採 deferred 更新，不強制重啟執行中簽核工作。手動重新查詢沿原接口；不預先準備或提交簽核。

正式部署須完整 CI、已合併 main、最新完整 Worker 包、精確模組差異及私人回退。其餘模組、Assets、秘密、bindings、設定與排程保持。發布後重新以原瀏覽器及 LINE 指令量測，手機實機另行驗收。
