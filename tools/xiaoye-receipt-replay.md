# Event receipt reconciliation candidate

This isolated candidate reuses an already saved `event-complete` or `event-fail` operation and its exact original body, without starting a new Codex turn. The Durable Object verifies the original event, source and lease, records the operation fingerprint before any D1 notice, and rejects a conflicting retry. A terminal receipt can be reread only when its stored fingerprint and current source match. Historic receipts with no fingerprint cannot be verified this way.

For a future interruption after the D1 failure notice commits but before DO finalization, the same D1 batch records the matching event, task, source, operation and fingerprint. Only an exact match with the DO's previously saved intent can finish that same failed receipt. Generic event checks are rejected after a finalization intent exists; no permission to continue the original execution is granted. Missing or inconsistent evidence, changed source, revoked lease or an older notice without a proof is held. This is evidence about an event receipt, not proof that all child processes or external writes stopped.

Run the ordinary local tests with `node --test tools/test-xiaoye-event-recovery.cjs tools/test-xiaoye-recovery-bridge.cjs tools/test-xiaoye-event-bridge.cjs`. For full Worker/D1/DO tests, set `DAILYLOG_XIAOYE_PACKAGE` to a fresh isolated bundle made from the latest complete Worker snapshot plus the candidate `xiaoye-secretary-events.mjs` and `xiaoye-secretary-dailylog.mjs`; set `DAILYLOG_XIAOYE_FIXTURE` to the reviewed `tools/xiaoye-repro-fixture.cjs`, then run `node --test tools/test-xiaoye-receipt-replay-worker.cjs`. The two crash tests additionally require a separate test-only bundle that throws once directly after the D1 notice and before the DO save, and `DAILYLOG_FAULT_INJECTION=1`; never deploy that instrumented bundle. The fixture uses only generated accounts, synthetic credentials and an empty D1. Tests do not represent live LINE delivery or production acceptance.
